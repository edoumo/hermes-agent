# H2.1 B1 runtime bridge fix

Status: ready for targeted real-runtime requalification.

## Failed recipe baseline

The real H2.1 recipe at commit `a9fdad69800986504e222273798eba989634a1d3`
returned `H2_1_REAL_RUNTIME_STATUS=PARTIAL`.

The HTTP control surface, auth, session isolation, inbox idempotency, DAG,
SSE, privacy, serialization, crash recovery and native API regression checks
passed. Real model execution was blocked before subagent launch.

## Root cause

`DurableWorkersAPIServerAdapter._dw_execute_reserved_sync()` called the native
`APIServerAdapter._create_agent()` with two unsupported keyword arguments:

* `requested_runtime`
* `route_source`

The native contract accepts `requested_model`, `requested_provider` and
`model_options` instead.

The background failure happened after the durable reservation had already
moved the activation/message/worker to STARTING/PROCESSING/RUNNING, so the
state remained fail-closed until crash recovery.

## Fix

Plugin version `0.2.1` routes the opt-in H2.1 factory through
`DurableWorkersRuntimeAPIServerAdapter`.

The runtime bridge now calls `_create_agent()` with the native contract:

* `session_id`
* `requested_model`
* `requested_provider`
* `model_options`
* `route`
* `session_model`
* `confirmed_runtime_lock`

It deliberately does not send `requested_runtime`, `route_source`, or a
launch-level `timeout_seconds`.

A pre-launch parent construction failure now also restores the already
reserved durable state immediately as:

* activation: `FAILED_TO_START`
* message: `PENDING`
* worker: `DORMANT`

This avoids requiring a process restart merely to recover a failure that
occurred before any subagent existed.

## Regression coverage

`tests/gateway/test_api_server_durable_workers_runtime.py` verifies both:

1. the exact `_create_agent()` keyword contract;
2. immediate durable reservation restoration when parent construction fails.

The platform factory tests now assert the runtime adapter is selected only
when `durable_workers_api` is explicitly enabled.

## Targeted requalification

Do not repeat already-passed H2.1 tracks unless a smoke check detects a
regression. Requalify the paths previously blocked by B1:

1. real activation 1 to SUCCEEDED;
2. real activation 2 with functional durable-context continuity;
3. global activation capacity while a real activation remains live;
4. Gateway drain / cooperative cancellation with a real subagent;
5. targeted regression tests including the new runtime bridge tests;
6. runtime-main integrity before/after.

A PASS may upgrade the prior PARTIAL verdict only when those blocked tracks
are green and the previously-passed surface remains smoke-clean.
